# METAL : affectations clavier R / C, 17 novembre 2026

Demande : R pour la vue première/troisième personne ; C pour esquiver avec le lourd ou descendre avec le drone. Base : `686582594c54d88e35d24c01bee9f36d099f15bf`, branche `codex/flight-fixes-20261117`.

## Corrections

Les valeurs R et C étaient déjà présentes dans les défauts 0.12.6, mais le numéro de format restait à 2 : une table enregistrée avec vue=C et esquive=R conservait donc l'ancienne disposition. Le format clavier passe à 3. Le couple historique exact est migré une seule fois, sans modifier les autres affectations ou réglages. Un couple C/R volontaire enregistré ensuite en version 3 est conservé. Les anciennes données ne permettaient pas de distinguer une inversion volontaire identique au couple historique : seule cette paire exacte des versions antérieures est traitée comme ancien défaut.

La normalisation d'une table partielle pouvait également rejeter toutes les affectations lorsqu'une touche explicite entrait en conflit avec le défaut d'une action absente. Les choix explicites sont maintenant réservés en premier ; les actions manquantes utilisent leurs alias libres, puis une touche libre si nécessaire. Deux choix explicites en conflit restent refusés, sans échange silencieux. Les alias AZERTY/QWERTY et les boutons manette sont préservés. Les migrations anciennes ne sont plus appliquées aux données clavier courantes.

L'attente périmée de C pour la vue dans `checks/options.test.mjs` est corrigée. Le cas simulant un ancien clavier indique explicitement sa version 2 et son ancien R pour l'esquive, au lieu de fabriquer une table incohérente avec les nouveaux défauts.
